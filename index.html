AbstractFigure 1

Layout estimation as a sequence of decisions

One-shot regressors predict every box at once, so a single mistake can break support and contact for the whole room. We perceive first, then plan corrections.

Building structured 3D scene layouts from a single image requires reconciling visual observations with physical and spatial constraints, a challenge that is difficult to address with direct prediction alone. In this work, we formulate monocular 3D layout estimation as a perceive-then-plan problem with vision-language models, where a Perceiver first grounds the 3D objects and then a Planner iteratively refines the scene hypothesis through actions that improve physical plausibility while preserving consistency with the input image.

We propose Layout-as-Policy (LaP), which casts the planning stage as a policy learning problem: 3D layouts are represented as structured states, and refined via discrete actions such as translation, rotation, and rescaling. Starting from an observation-aligned initialization with the geometry-enhanced Perceiver, the LaP Planner is trained to produce action sequences that progressively resolve geometric inconsistencies and enforce realistic spatial relations. To enable effective learning, we combine supervised sequence initialization with preference-based optimization, allowing the model to learn corrective behaviors without requiring explicit reward engineering.

This formulation transforms layout estimation from a one-shot prediction task into an iterative refinement process, enabling better handling of global constraints and complex object interactions. Experiments demonstrate that our approach produces layouts that are more physically coherent and better aligned with visual observations, while naturally supporting downstream tasks such as scene editing and manipulation.

§3 MethodFigure 2

Two VLMs, one closed loop

The Perceiver supplies a visually grounded starting point. The LaP Planner corrects its physical and relational errors. Pick a stage to see what it does.

Local-axis box representation

Regressing eight box vertices needs strong format priors that do not suit a VLM's training objective. Each box is instead a center, a size, and its two bottom axes; the vertical axis follows from a cross product.

ax_y = ax_x × ax_z Box = {(x, y, z, w, h, l, ax_x, ax_z, cls)} Without it: Reproj. IoU 0.54 → 0.41

Geometry-aware feature modulation

Fine-tuning alone fixes the output format but barely improves 3D grounding. Features from a frozen VGGT encoder regress FiLM coefficients and a spatial gate that inject geometry into the VLM's visual tokens. Thanks to the residual form, the fused features start out close to the 2D ones.

F = g ⊙ [(1+Δγ) ⊙ F3d + β] + (1−g) ⊙ F2d g = σ(MLP(F3d)) Removing it as well: Avg. DE 0.10 → 0.18 m

Grid-based canonical layout

Gravity is the dominant axis from an SVD of all bottom-face normals. The scene is rotated into a gravity-aligned frame, centered on the ground plane, and discretized into integer grid indices.

g = round((v − o) / δ) δ = 0.1 m gθ = round((θ + π) / (2π/Nθ)) Nθ = 24 1 cell = 10 cm · yaw in 15° bins

The layout is a state

Each object is written out as text: id, class, its 2D box (0–1000), grid position, size, and yaw index. The Planner sees this state together with the image.

obj_0 cabinet pos: [gx, gy, gz] size: [gw, gh, gl] yaw: 0–23

Refinement is a policy

The LaP Planner (Qwen3-VL with LoRA) predicts an action sequence. An action executor applies it to produce the next state, which is fed back with the same image.

L(t+1) = execute(L(t), π(I, L(t)))

Several short rounds

Fixing every inconsistency at once is a combinatorial problem. Each round resolves a few violations, and refinement stops when the Planner outputs only <STOP> or hits the round limit.

LaP 8B collisions: 3.62 → 3.23 after 1 round, 1.44 at convergence

Contact graph

Real assets rarely match their boxes exactly. With the LoRA adapter disabled, the same Planner backbone labels every object as resting on the FLOOR, ON another object, or FREE (wall-mounted or hanging).

<CONTACT> id: 2 class: pillow relation: ON 3 </CONTACT>

Relational bundles

A supporter and everything stacked on it move as one rigid composite, so a pillow never drifts away from its bed. FREE objects keep their refined position.

Gravity settling

A single-pass rigid-body simulation under a floor constraint removes the floating and penetration artifacts left by asset–box mismatch. The result is a digital twin, or boxes projected back to camera space for 3D grounding.

§3.2 Layout-as-PolicyFigure 3

Five actions, learned from preferences

A compact action space covers the Perceiver's dominant failure modes: misplaced position, wrong height, wrong scale and wrong orientation. Judging which of two action sequences is better is easier than defining the single best one, so the Planner learns from preference pairs instead of a hand-made reward.

action space · integers only
  • SELECT obj_N

    Choose which object the following actions edit.

  • MOVE [dx, dy, dz]

    Shift along the ground plane (dx, dz) and vertically (dy), in 10 cm grid cells.

  • ROTATE_Y [d]

    Turn around the vertical axis by d × 15°.

  • RESIZE [d]

    Rescale all three box dimensions uniformly.

  • STOP

    End the current sequence. A lone STOP means the layout is done.

Rules: select before correcting, fix the largest errors first, prefer fewer actions.

  1. Synthesize perturbed layouts

    Start from a ground-truth layout, sample an object and apply random, non-repeating perturbations from the action space; continue with probability p. Inverting the perturbations gives the ground-truth corrective sequence.

  2. SFT warm-up

    Supervised fine-tuning on these pairs teaches the output format and a basic reading of action, layout and image together, before the Planner ever sees noisy Perceiver outputs.

  3. Direct preference optimization

    The ground-truth sequence is the chosen sample. Perceiver-initialized trajectories and degraded copies of the ground truth are rejected samples.

    Numerical shiftRight direction, wrong magnitude.
    Nuisance actionsNo-ops, duplicates, edits to correct objects.
    Missing actionsPartial fixes or a premature STOP.
    Wrong typesMOVE swapped for ROTATE_Y, or flipped signs.

Planner training mix (SFT and DPO)

  • 20% ground truth, answer is STOP
  • 30% Perceiver-initialized
  • 50% synthetic perturbations

Fig. 3DPO pair synthesis. Perturbing a ground-truth layout and inverting the perturbation yields the selected sequence; degrading that sequence yields rejected ones. Sequences can touch multiple objects.

Perturbations create the same kinds of conflict the Perceiver produces, such as collisions and broken support, so the Planner learns visual alignment and physical plausibility in the same training phase. For DPO pairs built from Perceiver outputs, a candidate is kept as preferred only if it clearly improves layout-quality metrics on the same set of objects; ambiguous pairs are discarded.

§4.4 ApplicationsFigures 8, 9

The action space is also an editing interface

Because the Planner speaks in actions, a user instruction becomes an action sequence over the same vocabulary. No new architecture is needed.

Language-guided editing

Instructions are translated into actions that change the layout while keeping it plausible. The edited layout and the recovered scene are shown together.

Instruction“Put bottle_0 right above stove_0”

Instruction“Put the stove on counter_1”

Instructional refinement

A user can point out what looks wrong, and the Planner answers with the corrective actions. This makes it a natural component for interactive agentic systems.

User“The sofa_0 and the table_0 are too close to each other, should be more separated”

LaP Planner<SELECT> sofa_0, <MOVE> (0, 0, 4), <STOP>
